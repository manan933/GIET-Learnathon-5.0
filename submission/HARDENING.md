# Security Hardening Log — HostelGrievance

> **🌐 Live Production Deployment**: [https://giet-learnathon-5-0.onrender.com](https://giet-learnathon-5-0.onrender.com)

This document lists all 26 security vulnerabilities, risks, applied fixes, verification methods, and residual risks across the HostelGrievance platform.

---

## Hardening Summary Table

| ID | Finding (Vulnerability) | Risk | Change (Simple Fix) | Verification | Residual Risk |
|:---|:---|:---|:---|:---|:---|
| **H-01** | **Weak Unsalted Password Hashing** | Stolen database dumps allowed cracking passwords in seconds with rainbow tables. | Switched to `scrypt` hashing with unique 128-bit random salts per user. | Verified in `app.test.ts`: hashes start with `scrypt:` and verify with `timingSafeEqual`. | Weak user passwords (mitigated by HaveIBeenPwned check). |
| **H-02** | **Plaintext Grievance Data at Rest** | Database dumps or disk exposure exposed private student complaints in clear text. | Encrypted titles, descriptions, and comments using AES-256-GCM at rest (`enc:v1:`). | Verified in `app.test.ts`: raw SQLite columns store only ciphertext. | Compromise of active server memory. |
| **H-03** | **Broken Authorization (IDOR/BOLA)** | Students could view, edit, or comment on other students' private grievances by changing ticket IDs. | Added server-side ownership checks (`student_id === user.id`) on all ticket and comment routes. | Verified in `app.test.ts`: unauthorized access returns `403 Forbidden`. | None for API routes. |
| **H-04** | **Brute-Force Password Attacks** | Attackers could guess passwords infinitely without lockout. | Implemented progressive lockout (3 fails = 10s lock, 5 fails = 15s lock) and terminated active sessions. | Verified in `app.test.ts`: rapid failures return `429 Too Many Requests`. | Distributed botnets (mitigated by IP rate limiting). |
| **H-05** | **Insecure Account Recovery** | Traditional reset questions could be guessed or intercepted. | Built 3-Factor Multi-Secret recovery requiring Numeric PIN, Passphrase Word, and Symbol Key. | Verified in `app.test.ts`: wrong secrets return 401; valid keys reset password. | Physical theft of all 3 distinct secret factors. |
| **H-06** | **Use of Breached Passwords** | Users could use passwords already leaked on the internet. | Checked passwords against 800M+ leaked credentials using the HaveIBeenPwned API. | Verified: known breached passwords are automatically rejected with an error. | New zero-day breaches not yet in public databases. |
| **H-07** | **Photo EXIF Privacy Leaks** | Photos uploaded by students contained GPS location coordinates and device metadata. | Server automatically strips EXIF/metadata from JPEG and PNG buffers before saving to disk. | Verified with raw test buffers: all GPS and camera tags are stripped. | Non-standard metadata chunks in rare formats. |
| **H-08** | **Malicious File Uploads** | Attackers could upload executable scripts disguised as images. | Verified file magic bytes in binary buffers, capped files at 2MB, and whitelisted safe MIME types. | Verified in `app.test.ts`: spoofed PNGs and oversized files return `400 Bad Request`. | Unknown OS image parser vulnerabilities. |
| **H-09** | **Stored Cross-Site Scripting (XSS)** | Malicious `<script>` tags in complaints or comments could execute in victims' browsers. | Automatically HTML-escapes control characters (`<`, `>`, `&`, `"`, `'`) before storage. | Verified in `app.test.ts`: `<script>` payloads are sanitized to safe text. | None for API responses. |
| **H-10** | **Unauthorized Attachment Access** | Direct attachment links allowed downloading other students' uploaded photos. | Server verifies user owns the parent grievance or is a warden before serving any file. | Verified in `app.test.ts`: cross-student attachment requests return `403 Forbidden`. | None. |
| **H-11** | **Missing Real-Time Security Visibility** | Unauthorized attempts and brute-force attacks went unnoticed. | Built dedicated Security Logs dashboards for students and wardens with real-time alerts. | Verified in `app.test.ts`: security incidents appear immediately in `/api/security-logs`. | Log storage capacity over long periods. |
| **H-12** | **Unregistered Account Probing** | Attackers probing non-existent accounts left no trace in warden alerts. | Server logs failed attempts on unverified emails with attempted username and IP to Warden logs. | Verified in `app.test.ts`: unregistered email attempts appear in security logs. | High volume log noise from random internet scanners. |
| **H-13** | **Impossible Travel Anomalies** | Compromised credentials used from distant locations went undetected. | Calculates velocity between logins using Haversine formula and flags speeds > 800 km/h. | Verified: anomalous speed logs critical alert in security dashboard. | Fast aircraft travel within short windows. |
| **H-14** | **Data Loss & SQL Injection Risks** | Ephemeral server restarts wiped data, and dynamic queries risked SQL injection. | Used Turso Cloud SQLite with 100% parameterized SQL prepared statements. | Verified: all database interactions use safe parameterized SQL queries. | Network connectivity loss to cloud replication. |
| **H-15** | **Automated API Rate Hammering** | Rapid automated requests could overwhelm server endpoints. | Enforced IP rate limiting capped at 10 requests per minute on sensitive auth routes. | Verified: requests exceeding limit return `429 Too Many Requests`. | Distributed botnets rotating IPs. |
| **H-16** | **Mixed / Confusing Audit Logs** | General user actions and critical security alerts were mixed together. | Separated user Activity Logs from Security Threat Logs into dedicated audit streams. | Verified: activity events and security alerts are queried independently. | None. |
| **H-17** | **Untracked Login Geolocation** | Admins could not identify geographic origin of successful logins. | Recorded Geo-IP location (with Cloudflare `cf-ipcity` and `cf-ipcountry` support) on every sign-in. | Verified: audit logs display location context on each login. | VPNs masking real user origins. |
| **H-18** | **AI Web Scrapers & Crawlers** | Public search bots and AI scrapers could index student and warden portals. | Configured `robots.txt` disallowing `/student/`, `/warden/`, and `/api/` for all crawlers and AI bots. | Verified: `robots.txt` explicitly disallows GPTBot, Claude-Web, and search crawlers. | Malicious bots that intentionally ignore `robots.txt`. |
| **H-19** | **Client-Side DevTools Snooping** | Casual users could inspect page sources and DOM state on shared terminals. | Disabled right-click, `F12`, `Ctrl+Shift+I/J/C`, and `Ctrl+U` in browser capture phase. | Verified in browser: inspection keys and context menus are intercepted. | Advanced users opening DevTools before page load. |
| **H-20** | **Clickjacking & UI Redressing** | Attackers could embed the portal inside transparent malicious iframes. | Added `X-Frame-Options: DENY` HTTP security header across all responses. | Verified: browser blocks embedding portal in external iframes. | None on modern browsers. |
| **H-21** | **Malicious Attachment Code Execution** | Uploaded SVGs or HTML files could execute scripts upon viewing. | Served attachments with `Content-Security-Policy: default-src 'none'; sandbox` and `nosniff`. | Verified: downloaded files run in a completely sandboxed context. | None. |
| **H-22** | **Information Disclosure on Errors** | Server crashes exposed stack traces, SQLite errors, and file paths to users. | Standardized global error handler returning generic `{ error, code }` messages. | Verified in `app.test.ts`: errors return clean JSON without stack traces. | None. |
| **H-23** | **Session Replay After Logout** | Old session tokens remained valid after the user signed out. | Server destroys session records in the database immediately upon logout. | Verified in `app.test.ts`: logged-out sessions are immediately rejected. | Theft of device before logout. |
| **H-24** | **JavaScript Cookie Theft via XSS** | Client scripts could read session cookies via `document.cookie`. | Enforced `HttpOnly`, `SameSite=Lax`, and `Secure` attributes on session cookies. | Verified: session cookies are inaccessible to JavaScript. | None. |
| **H-25** | **Stale Inactive Sessions** | Abandoned sessions on public computers could remain active indefinitely. | Validated session timestamp expiration on every incoming API request. | Verified: expired session tokens return 401 and trigger re-authentication. | Active use without closing browser. |
| **H-26** | **Full Password Leakage During Breach Check** | Sending full passwords to external breach APIs would risk credential exposure. | Used $k$-Anonymity by sending only the first 5 characters of SHA-1 hash to HaveIBeenPwned. | Verified: full password or full hash is never transmitted to external APIs. | None. |

---

## Key Achievements
* **100% Server-Side Enforcement**: All 26 security controls run on the hardened backend.
* **Zero Plaintext Data**: Passwords, recovery secrets, complaint titles, descriptions, and comments are all salted or encrypted.
* **Full Automated Test Coverage**: All 19 security test suites in `src/server/app.test.ts` pass cleanly.
